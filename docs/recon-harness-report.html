1. 한눈에 보는 실행 흐름

정찰 하네스는 “컨테이너가 수집·실행만 하고, 검증은 호스트 게이트가 파일에서 독립적으로 다시 계산”하는 구조다. 컨테이너 안에서 무슨 주장을 하든, 호스트가 실제 파일에서 해시와 인용을 재계산하므로 거짓이 통과하지 못한다.

┌─────────────── 호스트(로컬) ───────────────────────────────┐
│  오케스트레이터(Claude Code)                                │
│    │  위임 (콜드 스타트 서브에이전트)                        │
│    ▼                                                        │
│  서브에이전트 ── docker compose up -d ──▶ recon 컨테이너    │
│              ── docker exec recon <명령> ──▶ (수집·실행)   │
│    ▲                                  │  원본 + 해시          │
│    │  독립 재검증                      ▼                      │
│  게이트(check-recon.mjs) ◀── 마운트 볼륨  targets/           │
│    (해시·인용 재계산 → GO/REVISE/STOP)                        │
└──────────────────────────────────────────────────────────────┘

전체 파이프라인은 PLAN → GO → RUN → CHECK 4단계로 나뉜다.

단계무엇을 하나승인예
PLAN수동 수집·정규화·핑거프린트·AI 추론불필요(저위험) collect_web.py, fingerprint.py
GO능동 정찰 승인사람의 GO <recon_id> GO RECON-02
RUN포트·디렉터리·vhost·DNS·프로브GO + --approved active_recon.py
CHECK2차 재검증 → 발견 확정 → 보고사람 판정 second_pass.py, check-recon.mjs

2. 시작 전 준비 (셋팅)

2.1 scope.md · 타깃 워크스페이스

모든 정찰은 허용 대역 안에서만 한다. scope.md가 대역을 선언하고, 게이트가 이를 읽어 대역 밖 타깃이면 STOP한다. CTF 대역 확정 시 반드시 갱신해야 한다.

# scope.md (CTF 당일 실제 대역으로 교체)
허용 대역: 10.10.110.0/24, 10.10.111.0/24
<!-- 예시 대역은 주석 안에만 — 게이트는 주석을 제거한 뒤 파싱한다(T19#5) -->

타깃 하나마다 워크스페이스를 만든다. 생성 직후 디렉터리 모습:

node scripts/new-target.mjs 10.10.110.5
created targets/10.10.110.5/  (findings.json, report.md, captures/)
다음: python scripts/collect_web.py <url> --target 10.10.110.5
targets/10.10.110.5/
├── findings.json          # 발견(제품·버전·provenance·근거) — 하네스 간 계약
├── report.md              # 보고서 템플릿
└── captures/
    ├── raw/               # 원본 자산(JS/CSS/HTML/헤더/쿠키) — gitignore
    ├── normalized/        # 정규화본(beautify·언패킹) — gitignore
    └── observation/       # 관찰: 응답·쿠키·도구 출력·자체로그 — gitignore

2.2 Docker 세션 시작

도구 환경은 이미지로 고정한다. 장수 컨테이너 모델이라 세션에 한 번만 띄우고, 이후 명령은 docker exec로 투입한다(명령마다 재시작하지 않음 — chromium 등 무거운 도구와 세션 상태 유지).

# 1) 빌드 → digest 를 compose.yaml 에 고정 (환경 결정론화)
docker build -t recon-harness -f docker/Dockerfile .
docker images --no-trunc --format '{{.ID}}' recon-harness
#   -> sha256:f5478de0c5bb...  (docker/compose.yaml 의 image: recon-harness@sha256:... 에 기록)

# 2) 세션 시작 (한 번)
docker compose -f docker/compose.yaml up -d

# 3) 명령은 래퍼로 투입 (없으면 up -d, 실행 후 manifest 에 runtime_image_digest 기록)
node scripts/recon.mjs python scripts/collect_web.py http://10.10.110.5/ --target 10.10.110.5

# 4) 세션 종료 (Cleanup)
docker compose -f docker/compose.yaml down
컨테이너가 하는 일
  • 이미지 안에 고정된 도구: nmap · gobuster · cariddi · playwright(chromium) · python 의존성
  • 마운트 볼륨: ./targets:/work/targets, ./scope.md:/work/scope.md:ro, ./wordlists:/work/wordlists:ro
  • 컨테이너는 증거(원본 파일)를 쓰기만 한다. 검증은 호스트 게이트가 한다.
Windows Docker Desktop 주의

컨테이너 안의 localhost는 컨테이너 자신이다. 호스트의 로컬 서버를 수집하려면 http://host.docker.internal:포트/를 쓴다.

3.3 헤더·쿠키 1급 자산 (T9)

응답 헤더와 쿠키도 일반 자산으로 승격된다 — 따라서 시그니처 매칭·근거 바인딩·게이트 재검증이 그대로 적용된다. 쿠키 값 원문은 gitignore 대상인 captures/raw/에만 있고, 지문은 이름·플래그·형식만 쓴다.

4. 정규화 · 결정론 핑거프린트

난독화 JS는 beautify·언패킹 후 지문을 뽑는다. 목표는 복호화가 아니라 기계가 매칭 가능한 정규화다.

python scripts/normalize_js.py 10.10.110.5
python scripts/fingerprint.py 10.10.110.5
[*] 47 signatures loaded
[*] findings: 12 (confirmed=1 inferred=10 guess=1), unmatched=0
[*] written: targets/10.10.110.5/findings.json

fingerprint.py는 harness/signatures/*.json 규칙(데이터)을 자산에 매칭한다. confirmed = 근거 문자열이 파일에 바이트 그대로 실재. inferred = API/관용구로 도출한 범위. unknown = 판단 불가(정답).

실제 픽스처에서 나온 발견 예시(FND-002, FND-012 등 요약):

finding_id제품버전provenance근거(evidence_quote)
FND-001Werkzeug3.0.1confirmedServer: Werkzeug/3.0.1
FND-002Djangounknowninferredcsrftoken (쿠키 이름)
FND-003Djangounknowninferredsessionid (쿠키 이름)
FND-004Flaskunknownguesssession= (서명 형식)
FND-005Djangounknowninferredaction="/admin/login/
FND-012Flask>=3.0inferredmap: Werkzeug 3.0.1 → Flask 릴리스 시기
버전 매핑·해시 DB (T11)
  • Werkzeug → Flask: confirmed Werkzeug 버전을 maps/werkzeug-flask.json으로 Flask 릴리스 시기(inferred)로 변환. 정확한 Flask 버전이 아니라 "시기"다.
  • Django admin 정적 해시: maps/django-static-hashes.json은 공식 PyPI 릴리스 휠에서 추출한 sha256→버전. 자산 해시가 일치하면 Django 버전 confirmed. 재구축: python scripts/build_django_hash_db.py --versions ...
멱등 병합 (T18) — 데이터 유실 방지

fingerprint 를 재실행해도 다른 스크립트가 만든 발견을 파괴하지 않는다. 외부 출처 (active_recon.py:*, fallback-inference:*, second-pass, …) 는 보존하고 fingerprint 소유(generated_by: fingerprint.py)만 교체한다.

# findings.json — finding 하나의 완전한 구조
{
  "finding_id": "FND-001",
  "generated_by": "fingerprint.py",
  "asset_kind": "header",
  "product": "Werkzeug",
  "version": "3.0.1",
  "version_bound": "UNSET",
  "provenance": "confirmed",
  "evidence_path": "targets/10.10.110.5/captures/raw/__headers__.txt",
  "evidence_quote": "Server: Werkzeug/3.0.1",
  "asset_sha256": "ec8decec0681ce850e492b9a91b03862...",
  "reasoning": "signature werkzeug-server-header: Server 헤더의 Werkzeug 버전...",
  "verified_by": ["fingerprint.py:werkzeug-server-header"],
  "report_eligible": false
}

5. AI fallback · 2차 재검증

AI fallback (T2) — 결정론이 못 잡은 자산

시그니처가 못 잡은 자산은 unmatched[]에 보존된다. 이 자산만 서브에이전트가 harness/prompts/fallback-inference.md 계약대로 판단한다. 핵심 규칙:

  • 제품/버전은 자산에서 바이트 그대로 인용 가능할 때만 제시.
  • 출력은 inferred/guess/unknown만. confirmed 금지(AI 자가 승격 금지).
  • 판단 불가는 unknown — 모르면 모른다고 하는 게 성공.
python scripts/merge_fallback.py 10.10.110.5 judgments.json
[+] upgraded AST-001 -> FND-006 (guess) quote='recon-harness fixture site'
[*] merged=6 total findings, unmatched=2
[i] unknown 유지(보존): ['AST-005']
[!] 병합 거부(rejected) 2 — REVISE 대상:
    - {"asset_id": "AST-002", "reason": "evidence_quote not found in asset — fabricated"}

지어낸 인용은 병합 전 바이트 검증과 게이트 재검증이 이중으로 잡는다.

2차 재검증 (T3) — 맥락 제거 재판정

고가치 발견은 제품·버전을 알려주지 않고 증거(인용+원문 일부)만 주고 다시 판단한다. 판정이 어긋나면 confirmed → inferred로 자동 강등.

python scripts/second_pass.py 10.10.110.5 --prepare
python scripts/second_pass.py 10.10.110.5 --apply verdicts.json
[+] FND-001 support — provenance 유지(confirmed)
[!] FND-002 contradict — 1차 판정과 상충 → confirmed 에서 inferred 로 강등

6. 능동 정찰 (GO → RUN)

능동 정찰은 타깃 상태를 바꾸거나 부하를 주므로 사람의 GO <recon_id> + --approved 가 필수다. 승인 없이 실행하면 요청을 한 건도 보내지 않고 STOP한다.

포트/서비스 스캔 + 배너 → confirmed (T5)

node scripts/recon.mjs python scripts/active_recon.py 10.10.110.5 \
    --target 10.10.110.5 --recon-id RECON-02 --approved --nmap-args "-sV -p 8000"
[*] 실행: /usr/bin/nmap -Pn -sV -p 8000 10.10.110.5
[*] stdout/stderr/exit=0 -> targets/10.10.110.5/captures/observation/nmap-RECON-02.txt
[+] finding FND-010: http SimpleHTTPServer 0.6 (Python 3.12.3) (confirmed)

배너 원문이 observation/nmap-RECON-02.txt에 저장되고, 그 파일에 바인딩된다. 도구 출력이 근거이므로 confirmed.

서버사이드 프로브 (T12)

python scripts/active_recon.py 10.10.110.5 --target 10.10.110.5 --recon-id RECON-03 \
    --approved --server-probe --port 80
[+] probe django-admin-login        200 http://10.10.110.5/admin/login/ -> .../raw/08_html_8.html
[+] probe django-admin-base         200 http://10.10.110.5/static/admin/css/base.css -> .../raw/09_base.css
[*] fingerprint 재실행(프로브 자산 매칭)...

프로브 응답을 자산으로 저장하고 fingerprint를 재실행해 시그니처·해시 DB를 그대로 적용한다. Django admin base.css가 실제 파일이면 해시 DB로 버전 confirmed까지 나온다.

vhost 발견 (T4) — baseline 대조로 오탐 억제

python scripts/discover_vhost.py 10.10.110.5 --target 10.10.110.5 \
    --recon-id RECON-01 --approved --domain corp.htb
[*] baseline(random vhost) host=xswswsbzxckwrz.invalid status=404 size=41
[+] vhost 후보: admin.corp.htb   (상태코드 다름 (baseline 404 vs 200))
[+] vhost 후보: intranet.corp.htb  (상태코드 다름 (baseline 404 vs 200))
[*] 테스트 33건, 후보 2건
[*] 후보 vhost 는 사람이 확인 후 재수집하세요:
      python scripts/collect_spa.py http://admin.corp.htb/ --target admin.corp.htb --host-map admin.corp.htb=10.10.110.5

무작위 vhost 기준선과 상태/크기/해시를 비교해, 와일드카드 오탐은 걸러낸다.

DNS·서브도메인 (T17) / AWS (T14)

  • discover_dns.py --passive — 수집 자산에서 *.corp.htb 호스트 문자열 추출(저위험).
  • discover_dns.py --active --approved — 워드리스트 DNS 브루트. 해석 IP가 대역 밖이면 기록만.
  • aws_recon.py --s3-buckets --approved-for-public — 공인 AWS 접근은 사람 허용 필수. 메타데이터(169.254.169.254)는 "접근 신호"까지만 기록, 취득은 익스플로잇 하네스에 위임.

7. 게이트 검증 (GO / REVISE / STOP)

마지막 관문은 npm run check -- <target>이다. 코드가 아니라 게이트가 검증한다.

npm run check -- 10.10.110.5

GO — 모든 근거가 무결

TARGET=10.10.110.5 DECISION=GO

REVISE — 누락·미검증·조작

게이트는 파일에서 해시를 재계산하고 인용 바이트를 다시 찾는다. 지어낸 인용이나 형식만 맞는 해시는 fabricated로 잡힌다.

TARGET=x DECISION=REVISE
  - targets/x/findings.json#FND-999: evidence_quote not found in evidence_path file
    — quote may be fabricated rather than copied from the asset
  - targets/x/findings.json#FND-001: asset_sha256 does not match sha256(evidence file)
    — fabricated rather than computed

STOP — 스코프 위반

TARGET=192.168.50.7 DECISION=STOP
  - STOP scope.md: target 192.168.50.7 은 허용 대역(10.10.110.0/24) 밖 — 정찰 금지
판정조건예

8. 결과물 저장 위치

컨테이너는 /work/targets에 쓰고, 이는 호스트 ./targets에 실시간 마운트된다. 즉 결과물은 항상 호스트 로컬에 있고, 게이트가 그 파일들을 독립 검증한다.

targets/<host>/
├── captures/
│   ├── raw/                       # 원본 자산 (JS/CSS/HTML/헤더/쿠키/렌더DOM) — gitignore
│   │   ├── 00_html_0.html
│   │   ├── 01_jquery-3.6.0.min.js
│   │   ├── __headers__.txt        # 응답 헤더 (asset_kind: header)
│   │   ├── __cookies__.txt        # 쿠키 (asset_kind: cookie) — 값 원문은 여기만
│   │   └── 05_rendered_dom.html   # 렌더 DOM + react-fiber 지문
│   ├── normalized/                # 정규화본 (beautify·언패킹) — gitignore
│   └── observation/               # 관찰 — gitignore
│       ├── entry-error.txt        # 실패도 보존(삭제 금지)
│       ├── nmap-RECON-02.txt      # 능동 도구 stdout/stderr/exit
│       ├── server-probe-RECON-03.json
│       ├── extract-<host>.json    # 시크릿 원문(gitignore) — finding엔 마스킹만
│       └── external-links.txt     # 대역 밖/외부 링크 기록만
├── manifest.json                  # 자산 목록 + asset_sha256 + runtime_image_digest + produced_by
├── findings.json                  # 최종 발견(계약) — 하네스 간 인터페이스
├── self-repair-log.md/.json       # 자가개선 로그(T20)
└── report.md                      # 보고서

gitignore 대상: captures/raw/, captures/normalized/, captures/observation/. 민감정보(쿠키·시크릿 원문)는 저장소에 커밋되지 않는다.

9. 증거 규율 · 마스킹

provenance 4등급

등급뜻승격 조건
confirmed근거 문자열이 원본에 바이트 그대로 실재, 또는 결정론 도구 해시 일치evidence_path(실재 파일) + evidence_quote(실제 부분 문자열) + asset_sha256(재계산 일치)
inferred코드 패턴으로 도출한 하한/범위근거 자산 인용, 단정 안 함
guess약한 정황보고서에 추측으로만
unknown판단 불가정식 값. 모르면 이걸 뱉는 게 성공

AI는 confirmed로 자가 승격할 수 없다. 결정론 도구 매칭(fingerprint/active_recon/extract/discover/aws) 또는 second-pass 재검증이 있어야 한다(게이트가 verified_by로 강제).

바이트 기준 재검증

인용 대조·해시는 인코딩과 무관하게 바이트로 한다. 원본이 CP949/EUC-KR/UTF-8 BOM이어도 게이트는 evidence_quote의 UTF-8 바이트를 파일 바이트에서 직접 찾는다.

시크릿·쿠키 마스킹

# findings.json 에는 원문이 없다 — 형식 프리픽스 + 마스킹만
"evidence_quote": "AKIA",          # 형식 프리픽스(비밀 아님), 파일에 실재
"secret_masked": "AKIA...len=20",  # 앞 4자 + 길이
# 원문은 observation/extract-<host>.json (gitignore) 에만

11. 운영자 체크리스트

CTF 당일 (필수)
  1. scope.md 허용 대역을 실제 할당 대역으로 교체
  2. 접근 방식(VPN 등) 확정 시 docker/compose.yaml 접근 프로파일 채우기
  3. 이미지 빌드 후 digest 재고정(코드 변경 시마다)
  4. 워드리스트(SecLists 등)를 wordlists/에 배치
실행 중 규율
  • 능동 정찰은 반드시 GO <recon_id> 후 --approved
  • 스코프 밖 IP 관찰 시 즉시 STOP·자동 확장 금지
  • 실패·미매칭·UNKNOWN 삭제 금지(observation 보존)
  • 쿠키·시크릿 원문은 findings/report에 넣지 않음(마스킹)
  • 신뢰 앵커(게이트·계약)는 자가수정 금지 → STOP 후 사람 보고
하네스 간 인계 (다음 하네스)

findings.json이 계약이다. CVE 매핑 하네스는 confirmed (product, version)만 자동 진행하고, 그 이하는 재검증을 요구한다.
